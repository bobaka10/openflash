Android ROMs, explained in plain words.

What is a ROM? What is a bootloader? Why does my phone need a "recovery"? This page explains every word you will meet while installing a ROM, so nothing on the screen is a mystery.

The short version. Your phone has an operating system (Android) just like a computer has Windows. A ROM is a different version of that operating system. Installing one means replacing the old system with a new one. Phone makers lock their phones so this is not possible by accident, so a few extra steps are needed: unlock the phone, send it some files from a computer, and let it install them.

3. Words you will meet

Tap a word to read what it means. Each one also says where it shows up in the installer.

The basics

ROM

The operating system file you install. It contains Android plus the changes the ROM's authors made: how it looks, extra features, privacy settings and so on. The name comes from "read-only memory", which is a historical leftover. Today it simply means "a version of Android you can install".

Stock ROM vs custom ROM

Stock is what the phone shipped with from the maker (Google's Android on a Pixel, MIUI on a Xiaomi). A custom ROM is made by someone else, such as LineageOS or Pixel Experience. People install them to get newer Android on an old phone, remove bloatware or gain more control.

Official vs community build

An official build is released by the ROM's own project and tested by them. A community (or unofficial) build is made by one person, often as a hobby. It can be great, but the risk is higher, which is why the installer labels every ROM with one of these two tags.

Flash / flashing

Writing a file directly into one of the phone's storage areas. "Flash a recovery" means "write the recovery file into the phone".

GApps (Google apps)

Google Play, Gmail, Maps and the other Google apps. Some ROMs already include them and some do not, so you add them yourself in a separate step. The page of each ROM says which case it is.

Locking and unlocking

Bootloader

The first small program that runs when you press power. Its job is to check the system and start it. Because it can start anything, phone makers lock it so only their own software is allowed. Installing a custom ROM needs it unlocked.

Locked and unlocked bootloader

A locked bootloader refuses to accept any file that is not signed by the maker. An unlocked one accepts files from you. Unlocking is a deliberate step you request, and it erases all data on the phone on purpose, so nobody can unlock a stolen phone and read its owner's files. Some makers, like Xiaomi, make you create an account and wait a while before unlocking is allowed. Unlocking can void the warranty, and a few banking or payment apps may refuse to run on an unlocked phone. Step-by-step instructions are on the Unlock page.

OEM unlocking

A switch in the phone's Developer options that says "I am allowed to unlock the bootloader". It must be on before unlocking works.

The special modes

Fastboot (bootloader mode)

A mode where the phone shows a plain screen (often the word "FASTBOOT") and waits for a computer to send it files. This is where the installer writes the recovery. Because it belongs to the bootloader, it works even when Android is broken.

Fastbootd

A second, newer kind of fastboot that runs from inside recovery instead of the bootloader. Modern phones keep several partitions inside one big container (see "Dynamic partitions"), and only fastbootd can write into that container. Some ROMs need it.

Recovery

A tiny separate system whose only job is maintenance. From here you can erase data (factory reset), install a ROM and repair problems. It is the "installer disk" of your phone. It still works when Android will not start. Popular recoveries are TWRP, OrangeFox, Lineage Recovery and the recovery of Pixel Experience.

Sideload and ADB

ADB (Android Debug Bridge) is a way for a computer to talk to a phone over USB. Sideload is one thing it can do: send a ROM file from the computer to a phone that is waiting in recovery. You choose "Apply update, then Apply from ADB" on the phone, and the installer sends the file. OpenFlash does this directly from the browser, so you do not need ADB installed.

USB debugging

A setting in Developer options that lets a computer control the phone while Android is running. You often need it before unlocking, but not once you are in recovery.

WebUSB

A browser feature (in Chrome and Edge) that lets a web page talk to a USB device after you give permission. This is why OpenFlash can install a ROM without any program. The browser shows a window asking you to pick your phone, and it will not talk to anything you did not choose.

Inside the phone

Partition

Phone storage is split into separate areas with different jobs: boot (starts the system), system (Android itself), vendor (hardware code), recovery and data (your apps and files). Flashing means writing into one of them.

Slots (A/B)

Many newer phones, including the Pixel 4, keep two copies of the system: slot A and slot B. An update is written to the one you are not using and the phone switches over when it is done. If the update fails, the old copy still works. That is why the recovery of such a phone shows "Active slot: a" or "b".

Dynamic partitions / super

On newer Android the system, vendor and product areas are not separate. They live as flexible "logical" partitions inside one large partition called super, which can be resized. Some ROMs for older phones use a version of this too.

Kernel

The core of the system that talks to the hardware. A recovery and a ROM often need to use the same kernel version, otherwise the recovery cannot properly install that ROM.

boot.img and dtbo.img

boot.img holds the kernel and the first files used at start. On some phones, like the Pixel 4, the recovery is stored inside it. dtbo.img is a small file that describes the phone's hardware to the kernel. Installers flash both so the new system matches the phone.

vendor_boot.img

On newer phones (like the Pixel 6 series) part of the files used at start live in their own area called vendor_boot. Some recoveries need their own copy of it, so installers flash it together with boot.img.

Vendor and firmware

The manufacturer's hardware-specific code (modem, camera, Wi-Fi). A ROM usually relies on the vendor files already on the phone, which is why some ROMs ask you to be on a certain stock version first.

Wipe / format data

Erasing the data partition, which holds your apps, accounts and files. A fresh ROM normally needs a clean data partition, because the old data was made by a different system and can make the new one crash. Make a backup first.

Safety and checking

Checksum (SHA-256)

A 64-character "fingerprint" of a file. If your copy gives the same fingerprint as the one the author published, the file is exactly the right one and nothing was damaged in the download. The installer can check it for you, and the Guides explain how to get it yourself.

Codename

The short internal name of a phone model, like flame for the Pixel 4 or clover for the Mi Pad 4. Files are built for one codename and must never be flashed on another. The installer reads the phone's codename and stops if it does not match.

Brick, soft brick, bootloop

"Bricked" means the phone no longer works. A soft brick (stuck on the logo, or restarting again and again, which is a bootloop) is common and fixable: you go back to recovery or fastboot and install again. A hard brick (no screen, no sign of life) is rare and usually comes from writing wrong files into the bootloader area. See section 5.

Root

Giving apps full "administrator" power over the system. It is a separate topic from installing a ROM, you do not need it, and it can break some apps. OpenFlash does not do it.

OTA update

"Over the air": the normal system update from Settings. Some custom ROMs keep their own updater, others are updated by sideloading a newer file.

4. The journey, step by step

These are the stages of almost every ROM install, and what is really happening in each one.

  1. Back up your things. Everything on the phone will be erased. Copy photos, chats and files somewhere safe now.
  2. Unlock the bootloader. You tell the phone's maker you accept the risk. The phone erases itself as part of this. It is done once. The Unlock page walks you through it.
  3. Get the right files. Download the ROM and any helper files (recovery, boot, dtbo) for your exact model. Check their SHA-256 so you know they are genuine and complete.
  4. Start the phone in Fastboot mode. Hold the right buttons while powering on. The phone now waits for a computer.
  5. Connect from the browser and flash the recovery. The installer checks the phone's codename, then writes the helper files and the recovery into the phone.
  6. Boot into recovery. The phone starts the small maintenance system you just installed. You now see its menu.
  7. Format data. In recovery you choose Factory reset or Format data. This clears space for the new system.
  8. Send the ROM (sideload). You choose Apply from ADB on the phone, and the installer sends the ROM file over USB. The phone checks its signature and installs it. Do not unplug the cable.
  9. Reboot and wait. Choose Reboot system. The first start can take several minutes. Then you see the welcome screen of your new Android.

Most problems are small and fixable. Here are the common ones in plain order, from harmless to serious.

6. Questions people ask

Will I lose my data?

Yes. Unlocking the bootloader erases the phone, and installing a ROM erases it again. Everything you want to keep must be copied somewhere else first. After the install, apps and files do not come back on their own.

Can I go back to the original system?

Usually yes. Most makers publish their original software ("factory images" or "fastboot ROMs"), and you can flash it again. That also erases the phone. Pixels even have an official web tool for this (see the Guides).

Is it legal? Does it void the warranty?

In most countries you may change the software on a device you own. Warranty is a different matter: unlocking the bootloader can void it with some makers. Check your maker's terms before you start.

Why can I not just do it from the phone?

The phone's own Android cannot replace itself while it is running, and the bootloader's special modes only talk over USB. That is why you need a computer. Here it is the browser, so nothing needs to be installed.

Why is the first start so slow?

The new system has to set everything up from scratch: it builds its caches and prepares every app. Give it up to 10 minutes. That is normal.

Why do the steps differ between phones?

Phones are built differently. Some keep their recovery inside the boot file, some have two system slots, some need a Mi account to unlock. Each ROM's own instructions say which applies, and the installer follows them for each supported phone.

My banking app does not work after installing a ROM.

Some apps check whether the phone is "certified" and refuse to run if the bootloader is unlocked or the system is not the original. That depends on the ROM and the app, and it is up to the ROM's authors whether it can be solved.
